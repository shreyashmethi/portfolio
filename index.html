Production machine learning

A self-improving experimentation loop for production models

I led this program, for a Fortune 500 car rental company

A Claude agent proposes a change to the training code of a production model, retrains it, and keeps the change only if it beats the current best on out-of-time validation. Anything that fails a gate is reverted. The gates are tested with pytest and Hypothesis, and a hard budget cap stops runs before they cost more than agreed. It runs across five production models.

Claude API, Python, XGBoost, Optuna, pytest, Hypothesis

+9.5%

Recall@20% on the propensity model, from 425 experiment rounds that cost $31

Propensity and no-show models with a weekly retrain

Built and maintained, for a Fortune 500 car rental company

Models that predict which customers will buy each of five rental add-ons, and which bookings will be cancelled or not collected. Trained on 7.5 million records with strict out-of-time splits and Platt calibration, explained with SHAP, and promoted through champion/challenger gates on a weekly OCI pipeline. Along the way I found and fixed three kinds of feature leakage, in RFM ranks, lifetime-value features and cumulative counts, that had been inflating offline scores.

How I work

Distrust the offline score

Out-of-time splits, calibration and a hunt for leakage come before any tuning. A model that looks better in a notebook and worse in production hasn't improved.

Let agents propose, let tests decide

LLM agents are good at generating options and bad at judging them. I put tested gates and human review between what an agent suggests and what ships.

Show the source

An LLM answer should point to where it came from, and the system should notice when it doesn't. That's what the citation and provenance checks in my retrieval work are for.
